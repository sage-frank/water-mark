# 2026-09-14

## 环境：dxpdf 链接失败（Kylin V10）
- 报错：`/usr/bin/ld: cannot find -lfreetype` / `-lfontconfig`。
- 原因：系统只有运行时库 `libfreetype.so.6`、`libfontconfig.so.1`，缺开发用 `.so` 软链接。
- 处理：`yum install -y freetype-devel fontconfig-devel`（顺带升级 freetype 2.10.2-5 → -7，安装 libpng-devel/libxml2-devel/bzip2-devel/xz-devel 依赖）。之后链接通过。
- 注：之后 Kylin 镜像源 `update.cs2c.com.cn` 网络超时，无法再装包（如 poppler-utils 用于渲染验证），本机没有 pdftoppm/qpdf/gs/mutool/pypdf/pymupdf。

## 修复：lib.rs `add_xobject_to_page` 无法注入水印资源（WARN: 结构非标准…错误：Type）
- 现象：每页都打印 `WARN: 第 N 页结构非标准，无法注入资源。错误：Type`，且因 `continue` 跳过整页，
  输出 PDF 里**一个水印都没有**（`/Watermark1 Do` 出现 0 次）。
- 根因：PDF 里 `/Resources` 是内联字典，但 `/XObject 50 0 R` 是**间接引用**。
  旧代码 `resources.get_mut(b"XObject")?.as_dict_mut()?` 拿到 `Object::Reference` → `lopdf::Error::Type`。
- 修复（`src/lib.rs`）：
  1. 先只读解析出 `/Resources` 与 `/Resources/XObject` 的真实形态（间接引用 / 内联 / 缺失）；
  2. 写入阶段分三条最短借用路径：1) XObject 是间接对象 → 直接改它；2a) Resources 间接 → 改它；
     2b) Resources 内联在页面字典 → 走页面字典借用链。避免多层 `&mut Document` 借用冲突。
  3. 新增辅助函数 `ensure_subdict(dict, key)`：取子字典，不存在则新建空字典。
  4. import 增加 `Dictionary`。
- 验证：cargo 编译通过；运行无 WARN；4 页 `/XObject` 字典均含 `/Watermark1 169 0 R`；
  内容流共 52+ 条 `/Watermark1 Do`；对象 169 是 24KB 有效矢量路径（`/GS1 gs` + `0.1 0.1 0.1 rg` + `f`）。
- 未做：目视渲染验证（受限于无渲染工具 + 镜像源不通），建议用项目自带 `preview.html`（PDF.js）查看 `w-out.pdf`。

## 给 Python(ctypes) 用的动态库编译方式
- 命令：`cargo build --release --lib` → 产物 `target/release/libwater_mark.so`
  （Windows: `water_mark.dll`，macOS: `libwater_mark.dylib`；debug 版为 `target/debug/...`）。
- 必须带 `--lib`，否则会触发上面 convertd.rs 缺失的 target 解析错误。
- 该 .so 就是 `[lib] crate-type = ["cdylib", "rlib"]` 中的 cdylib 产物，导出 FFI 函数
  （如 `add_pdf_watermark`）供 PHP / Python 调用。
